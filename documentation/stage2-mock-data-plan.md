## 1. Principles

1. **Deterministic**: one generator script (fixed random seed `20260920`) produces identical data every run.
2. **Anchor month**: 1–30 September 2026 with "demo today" = **20 September 2026**, as in the prototype (UQ-20; real calendar date is 1 Nov 2026).
3. **Mandaveli is the fully populated depot**, matching the prototype's dashboard figures. Other depots get reasonable samples in three tiers.
4. **Referentially complete**: inserts follow dependency order; every FK resolves; verification queries run after load and must return zero violations.
5. **History is real**: current state is *derived* from movements, so tyre histories contain genuine fitments, rotations, TRS trips and transfers.
6. **No sensitive data**: no Aadhaar numbers (only a fictional last-4 field), no real phone numbers, no real emails, no real people, no real vendors, fictional GSTIN values.
7. **No credentials in the repo**: demo passwords are generated at provisioning time and printed once, or read from an untracked local file.

Master rows are loaded as live baseline (status ACTIVE), then the ~90 change requests are replayed through the real functions, so history and audit rows are produced by the same code the app uses.

## 5. Consistency rules the generator must satisfy

1. A fitted tyre has exactly one fleet+position; no two tyres share fleet+position; every operating Mandaveli fleet has 6 fitted tyres.
2. `tyre_current_state` equals the result of replaying `tyre_movements`; the last movement id is stored.
3. Each open fitment span ↔ a currently fitted tyre.
4. A tyre's `retread_level` equals the number of completed retread stages; a tyre at TRS has an open retread batch line.
5. Every GIN beyond APPROVED has a gate pass; IN_TRANSIT GINs have EXITED passes; RECEIVED GINs have a GRN; ledger inward at destination = outward at source (after in-transit).
6. Indent line issued/received quantities roll up to the indent status.
7. Tyre Changing cards have four tasks in order; Fitment never starts before Setting completes; Removal Order exists once removal is complete; Fitment Order exists once fitted.
8. Card status is consistent with task statuses (e.g. Awaiting final inspection only when all tasks are submitted).
9. Hold, cancel, reject, return, revert, withdraw rows all carry non-blank remarks.
10. Assigned person must be active, in the right depot, and not on approved leave for the shift (a few deliberate exceptions to demonstrate "On leave" warnings are flagged).
11. Master change requests: APPROVED ⇒ live row version incremented, `applied_at` set; PENDING/REJECTED/WITHDRAWN ⇒ live row unchanged; at most one open request per record; maker ≠ checker.
12. Dates are within the anchor month (or earlier for received/purchased/manufactured dates); no future-dated completed work.
13. Employee ↔ role ↔ depot rules (HO/AM no depot; others a DEPOT).
14. Totals reconcile with the prototype's Mandaveli dashboard numbers (§3.3).

## 6. Verification (run after load; each must return 0 rows or the expected count)

| Check | Method |
|---|---|
| Foreign-key integrity | all FKs are real constraints; any load failure aborts |
| Orphans / duplicates | query pack: duplicate fitted positions, fleets without 6 tyres, tyres in two places |
| State vs movements | rebuild `tyre_current_state` from movements in a temp table and diff |
| Ledger balance | per (unit, folio) running balance equals sum of inward − outward |
| Document chains | GIN→gate pass→GRN, indent→GIN completeness |
| Approval invariants | the list in rule 11 |
| Remarks | count of rejection-type rows with blank remarks = 0 |
| Dashboard parity | Mandaveli counts equal §3.3 |
| Privacy scan | regex scan for 12-digit numbers, real-looking emails, 10-digit mobile numbers |
| RLS smoke test | for each demo role, counts visible per table match expectations |

## 8. Reset and re-seed
A single command truncates demo tables in reverse dependency order (never in production) and reloads. The anchor date can be moved by changing `application_settings.demo_today` plus a re-seed offset, so the dataset can be refreshed for future demos.
